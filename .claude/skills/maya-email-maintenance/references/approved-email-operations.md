# Approved email operations

This route applies only when Oren explicitly authorizes mailbox maintenance or routine email sending. Installation and default REPORT_ONLY scheduling do not grant that authority. Resolve the current instruction before each run; a narrower prohibition such as no Monday writes overrides the bounce-correction exception.

## Execution and evidence

1. Verify the required workstation and exact configured Maya Gmail profile through the same connector that will perform the operation. Never substitute another account. Tool availability alone does not prove write permission.
2. Use one active mailbox run. If another run may still be sending, defer rather than overlap. Reuse the existing protected recipient/topic dedupe ledger for proactive sends; if it is unavailable, proactive sending is blocked, not cleanup or inbound classification.
3. Inspect new inbox mail with bounded pagination and the current draft inventory. Resume known open work separately; do not repeat a historical full scan. Keep a bounded continuation when the run deadline is reached and report PARTIAL.
4. Use the connector's documented label, message-modify, draft and send tools only within the current authorization. Do not execute a local worker or change its scope to work around an error. Existing local runtime flags describe that runtime, not a separately verified connector.
5. Verify every write by reading the affected message. After an uncertain send, inspect sent mail before any retry; if acceptance remains uncertain, stop that send and report it. Never resend because telemetry failed.
6. Report actual scanned, labeled, marked-read, archived, drafted, sent-and-verified, pending and blocked counts separately. Do not count a request as completed merely because it was forwarded or a reply was sent. Missing signed telemetry is TELEMETRY_GAP, not signed success. Do not attempt credential repair as part of a mailbox run.

## Cleanup

Classify before changing state. Archive only clearly low-risk newsletters, marketing clutter or administrative traffic whose required action is verified complete. Retain customer, lead, plans, service, finance and unclear correspondence in the inbox. Never delete or move to Trash. Mark read/processed only after classification and the required handling or escalation are complete.

## Inbound routine response

Within an existing verified customer or lead conversation, the standing scope permits acknowledgement and requests for missing operational facts. Read the full current thread, inspect relevant later Gmail correspondence and opt-outs, and confirm the response has not already been provided. Re-read immediately before sending. No price, discount, liability, material complaint, financial decision, legal/safety advice or new commitment is authorized. Do not send old reports, test drafts or stale customer drafts.

WhatsApp being disabled does not block cleanup or an otherwise verified response to new inbound email. If the specific response depends on information from an unavailable channel, keep that item pending.

## Proactive daily follow-up

A daily review is not daily contact. Preserve the skill's seven-day per-recipient/topic cooldown and two-unanswered-attempt limit. Read authoritative Monday stage and follow-up date without mutation and apply SALES_ELIGIBILITY_FILTER. Complete the existing cross-channel response checks. If WhatsApp is disabled or any required evidence is unavailable, do not activate it or silently weaken the check: keep the proactive item blocked and continue independent email work.

## Escalations and bounces

Before escalating an apparent unattended request, look for later Gmail correspondence and current updates on the exact Monday item. Subsequent verified handling suppresses the stale no-response escalation, but does not establish final resolution. Escalate only the unresolved decision with minimal context.

When Monday writes are prohibited, classify bounces and investigate the original recipient without correcting Monday or resending under the coupled bounce workflow. Keep the unresolved case visible. Marketing, broadcasts and new-recipient outreach are outside routine email approval.
