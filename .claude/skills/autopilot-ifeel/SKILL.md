# Autopilot i-feel

## העיקרון

רוץ לבד כל עוד הפעולה ניתנת לביטול ואינה משנה ייצור, לקוח, כסף או מידע משותף באופן
בלתי הפיך. עצור פעם אחת בלבד, ברגע האחרון לפני הפעולה החיצונית המוגנת.

## אזור ירוק

- מחקר וקריאה.
- עריכת קבצים בענף עבודה ייחודי.
- build, lint ובדיקות.
- יצירת מסמכים, תמונות, טבלאות וטיוטות.
- commit מקומי.
- העלאת ענף עבודה ופתיחת Draft PR דרך:

  ```powershell
  .\scripts\workstations\publish-work.ps1 `
    -CommitMessage "<message>" `
    -PrTitle "<title>"
  ```

- בדיקת Actions ו-verify-live בקריאה בלבד.

## אזור אדום

עצור וקבל אישור מפורש לפני:

- merge ל-`main`;
- אישור סביבת `production`;
- מחיקת קובץ, ענף, נתון, הודעה או קובץ שרת;
- שינוי secrets, branch protection או runner;
- שליחת מייל/WhatsApp/הודעה ללקוח;
- פרסום ברשתות או YouTube;
- שינוי קמפיין או פעולה כספית;
- שינוי שדה קריטי או פתיחת ליד במאנדיי.

## Git בשני מחשבים

- GitHub הוא מקור האמת.
- כל מחשב משתמש בענף `work/<computer>/<date>-<slug>` משלו.
- בתחילת משימה משתמשים ב-`new-work.ps1`, שיוצר ענף מ-`origin/main`.
- לפני push הסקריפט מריץ build, commit, ‏fetch ו-rebase.
- אין עבודה ישירה על `main`.
- אין שימוש באותו ענף משני מחשבים.
- אין force push.

## פריסה

- Claude ו-Codex אינם מעלים ישירות ל-JetServer.
- merge מאושר ל-`main` מפעיל GitHub Actions.
- ה-artifact המאומת נשלח ל-runner של מחשב המשרד ומשם ב-FTPS.
- אין מחיקות מרחוק.
- כשל runner או FTPS אינו היתר לעבור להעלאה ידנית.

## קווים אדומים

- לא ממציאים נתונים.
- לא מדפיסים secrets.
- לא מכניסים `.env`, credentials או פרטי FTP ל-Git.
- ליד חדש דורש טלפון ודוא"ל אמיתיים ובדיקת כפילות.
- sitemap ידני מתעדכן עם כל דף חדש.
- קבצים רגישים דורשים כוונה מפורשת.
