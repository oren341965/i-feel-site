# Daily SEO Crawl 3.0 — i-feel.co.il

## 🎯 North Star — מטרת העל

**i-feel.co.il במקום #1 בחיפוש אורגני בגוגל ישראל עבור:**
1. **`בית חכם`** — שולט על מסלול הלקוחות הפרטיים
2. **`בקרת מבנה`** — שולט על מסלול ה-BMS ומבני ציבור

כל ריצה של הסקיל הזה צריכה לקדם אותנו לעבר היעד הזה. הסקיל לא *מנטר* SEO — הוא *מקדם* את i-feel למעלה ב-SERP. אם דוח שלך לא מקרב אותנו למהלך ההתקפי הבא — חזור על התהליך.

מילת מפתח משנית (tier-2), למעקב בהמשך: `דירה חכמה` (מסלול היזמים — "razor" בעסקי הבית החכם).

## איך הדוח עוזר להגיע ל-#1

אורן קורא את הדוח 30-60 שניות בבוקר. צריך לצאת ממנו:
1. **היכן אנחנו היום** על שתי מילות העל (מיקום ומי מחזיק את #1-#3)
2. **מה הפער** — מה יש לאלה שמעלינו, שאין לנו
3. **המהלך ההתקפי הבא** — פעולה אחת שמקדמת אותנו (פוסט חדש, שיפור תוכן קיים, backlink, תיקון טכני שחוסם אותנו)

גרסאות 1.0 ו-2.0 הפיקו דוח ארוך ומגנתי (ציון, טבלאות, PSI). 3.0 מבוסס על:
- **Delta over state** — מה השתנה, לא מה קיים
- **Offensive over defensive** — מהלכים לקידום, לא רק תחזוקה
- **North Star focus** — 2 מילות על נמדדות עם קונטקסט תחרותי מלא; שאר המילים — רק שורה אחת

## מבנה הריצה

| מצב | מתי | כמה זמן | מה נסרק |
|-----|-----|---------|----------|
| `daily` (ברירת מחדל) | ימי חול, 07:00 | ~90 שניות | דף הבית + הפוסט האחרון |
| `deep` | יום ראשון, 07:00 | ~5 דקות | + 5 דפים קריטיים + מתחרים |
| `verify` | לפי בקשה | ~30 שניות | URL ספציפי לבדיקה של תיקון |

בברירת מחדל — תמיד `daily`. `deep` רק אם היום ראשון או אם אורן ביקש "סריקה מלאה"/"deep scan". `verify` כשאורן כותב "תבדוק שהתיקון עבד ב-{url}".

## סדר הפעולות

### 1. שליפת בייסליין מאתמול (15 שניות)
`conversation_search` עם query "דוח SEO יומי i-feel" — שלוף את הדוח של אתמול. זה מה שמאפשר דלתא. אם לא נמצא דוח קודם → זו ריצת bootstrap, ציין זאת בתחתית הדוח ורשום ערכים נוכחיים כבסיס.

### 2. סריקה ממוקדת (30-60 שניות)

**תמיד — דף הבית**:
`web_fetch https://www.i-feel.co.il/`

**תמיד — הפוסט האחרון**:
`web_fetch https://www.i-feel.co.il/post-sitemap.xml` → מצא את `<url>` עם ה-`<lastmod>` הכי חדש → `web_fetch` לפוסט עצמו.

**במצב `deep` בלבד — 5 דפים קריטיים**:
```
/smart-home/              (לקוחות פרטיים)
/construction-developers-2/  (יזמים)
/structure-control/       (BMS)
/quote-2/                 (המרה)
```

לכל דף — בדוק:
- HTTP status (צריך 200)
- `<h1>` count (בדיוק 1)
- `<title>` length (50-60 תווים)
- `<meta name="description">` (120-160 תווים)
- `<link rel="canonical">` נכון
- JSON-LD schema קיים
- og:title ו-og:image
- alt coverage (תן הערכה גסה — לא חייב מדויק)

**חשוב**: רק ממצאים שמסווגים 🔴 או 🟡 נכנסים לדוח. בדיקה שעברה בהצלחה לא מוזכרת.

### 3. Core Web Vitals (10 שניות)
קריאה אחת ל-PSI API לדף הבית, mobile בלבד (במצב `deep` גם desktop):

```
https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=https://www.i-feel.co.il/&strategy=mobile
```

שלוף רק 4 ערכים: Performance score, LCP, CLS, TBT. **ציין בדוח רק** אם:
- ירידה של ≥5 נקודות בציון Performance
- מעבר סף (למשל LCP מתחת 2.5 → מעל 2.5)
- CLS עבר 0.5 במובייל

אחרת — אל תזכיר. יציב = לא מדווחים.

### 4. אימות הפוסט היומי (20 שניות)
הפוסט נוצר ע"י סקיל נפרד (`daily-article-publisher`). כאן רק מאמתים שעלה תקין:

- ✅ Featured image מוצג (חיפוש `<img>` עם `wp-post-image` class או `<meta property="og:image">`)
- ✅ Word count ≥ 1,500
- ✅ Article או BlogPosting schema ב-JSON-LD
- ✅ Meta description קיים
- ✅ אינדוקס: `web_search: site:i-feel.co.il {כותרת}` — אם מופיע → ✅. אם עברו פחות מ-48 שעות מהפרסום → ⏳ (תקין). מעל 48 שעות ולא מאונדקס → 🔴.

### 5. מעקב North Star + מילות מפתח (30 שניות)

זה הסעיף הכי חשוב של הסקיל. הוא נותן את הקונטקסט להחלטות האסטרטגיות.

**לכל אחת משתי מילות העל** (`בית חכם`, `בקרת מבנה`):

א. `web_search: {keyword}` — שלוף את top 5 התוצאות.
ב. זהה את המיקום של `i-feel.co.il`. אם לא בתוצאות — סמן "מחוץ ל-top 5".
ג. תיעד מי מחזיק את #1, #2, #3.
ד. השווה ל-`conversation_search` של אתמול:
   - האם המיקום שלנו השתנה?
   - האם מתחרה חדש נכנס ל-top 3?
   - האם מישהו שהיה מעלינו נפל?

ה. **ניתוח פער** — לדף המחזיק ב-#1: `web_fetch` ונתח:
   - מה הכותרת (<title>)
   - מה ה-H1
   - אורך התוכן (גס)
   - האם יש schema עשיר (FAQ, HowTo, Article)
   - האם יש תמונות/וידאו
   - כמה H2 (מעמיקות התוכן)

ו. השווה לדף שלנו שמדורג על המילה הזו (אם יש — `web_search: site:i-feel.co.il {keyword}` → הדף הראשון).

ז. גבש **מהלך התקפי אחד** — המשימה השבועית שהכי תקרב אותנו ל-#1. דוגמאות:
   - "הפוסט של Vitrea 2,400 מילים, שלנו 800 → להרחיב פוסט קיים ל-2,500+"
   - "#1 יש FAQ schema, לנו אין → להוסיף 8 שאלות"
   - "#1 יש 3 סרטונים, לנו אין → להוסיף סרטון מה-YouTube שלנו"
   - "Higoal קפץ מ-#8 ל-#4 על 'בקרת מבנה' → לבדוק מה הם עשו"

**למילה ה-tier-2** (`דירה חכמה`) — רק שורה אחת: מיקום נוכחי + שינוי מאתמול.

**הערה טכנית**: בהיעדר Google Search Console API מוסמך, המיקומים הם *משוערים* מתוך `web_search`. ציין זאת בדוח. אם GSC MCP זמין — עדיף להשתמש בו לקבלת מיקום מדויק.

### 6. מתחרים על North Star — במצב `deep` בלבד (30 שניות)
פעם בשבוע (יום ראשון):
- **Vitrea** (vitrea-sh.com) — מתחרה ישיר על `בית חכם`, חזק בבלוג
- **SwitchBee** (switchbee.com) — מתחרה ישיר על `בית חכם`, חזק במוצר
- **HiGoal** (higoal.co.il) — מתחרה על `דירה חכמה` ליזמים
- **Priva / Honeywell ישראל** — מתחרים על `בקרת מבנה`

`web_search: site:{competitor_domain}` — חפש פוסטים חדשים מהשבוע שעבר.
**דווח רק אם יש פוסט שמכוון למילת מפתח שבה אנחנו נלחמים**. פוסט של Vitrea על "איך להתקין נורה" — לא רלוונטי. פוסט של Vitrea על "בית חכם 2026" — 🟡 דחוף.

### כללי הצגה
- **אורך מקסימלי**: 25 שורות. אם יותר — קיצצת לא מספיק.
- **North Star** הוא הסעיף הראשון אחרי השורה העליונה — הוא צריך להיות הדבר הראשון שאורן רואה.
- **המהלך ההתקפי**: משפט אחד. לא שניים. אם יש יותר מהלכים — בחר את הכי משמעותי.
- **משימות היום**: מקסימום 5. אם יש יותר, השאר את 5 הקריטיים ביותר ושלח את השאר ל-Monday כ-backlog.
- **לא לכלול**: טבלאות של מטריקות שעברו, פרטי PSI מלאים, הסברי why. אורן יודע למה CLS חשוב.
- **לא להסביר**: "CLS זה Cumulative Layout Shift..." — לא. רק הערך והפעולה.
- **אחראי**: אביחי = webmaster/Cloudflare/WP, אורן = אסטרטגיה ותוכן, שגיב = בקרת מבנה/יזמים, אורה = תכנון, קיריל = BMS. אם לא ברור — "לתיוג".

## תיקונים אוטומטיים

**רשאי לתקן ישירות** (ללא אישור נוסף, אחרי שהצעת ואורן אמר "תתקן"):
- הוספת meta description לפוסט בודד דרך WordPress MCP
- הוספת alt ל-תמונה בודדת חסרה
- Ping לגוגל דרך `https://www.google.com/ping?sitemap=...`
- עדכון Yoast focus keyword של פוסט

**אסור לתקן ללא אישור מפורש**:
- שינוי `<title>` או `<h1>`
- שינוי canonical
- שינוי `robots.txt`
- מחיקת תוכן
- שינוי סוג schema

## Post-fix propagation (אחרי תיקון)
אם הוחל שינוי באתר:
1. Cloudflare — הצע לאורן "אביחי יכול לעשות Purge Everything?"
2. Facebook OG debugger — אם שונו og: tags, הצג את הלינק: `https://developers.facebook.com/tools/debug/?q={url}`
3. GSC — הצג: `https://search.google.com/search-console` → URL Inspection → Request Indexing
4. אחרי 60 שניות — `web_fetch` עם cache-bust (`?cb={timestamp}`) כדי לאמת.
