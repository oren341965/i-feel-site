# 📬 Mailing List Collector — איסוף רשימת דיוור ל-i-feel

## מה הסקיל עושה

אוסף את כל מי ששלח מייל לתיבות i-feel בטווח תאריכים נתון + אנשי הקשר מלוח המכירות במאנדיי,
מאחד ומנקה כפילויות, מסווג את הקשר ואת הרשאת הדיוור בנפרד, ומפיק קובץ CSV מוכן לייבוא ל-Smoove.

**הסקיל קורא בלבד** — לא שולח מיילים, לא משנה כלום ב-Gmail או במאנדיי.

| פרמטר | ברירת מחדל אם לא צוין |
|--------|------------------------|
| טווח תאריכים | 30 הימים האחרונים |
| מקורות | Gmail (כל התיבות) + מאנדיי לוח מכירות |

אם אורן נתן תקופה ("מאז מאי", "החודש האחרון", "מ-1.6 עד היום") — המר לתאריכים מדויקים
בפורמט Gmail: `after:YYYY/MM/DD before:YYYY/MM/DD`. אין צורך לשאול אותו שאלות נוספות — פשוט רוץ.

## שלב 1 — סריקת Gmail (כל התיבות)

טען את כלי ה-Gmail (search_threads / get_thread) דרך ToolSearch אם אינם טעונים.

**חשוב להבין:** ה-connector של Gmail מחובר לחשבון אחד. תיבות המחלקות מגיעות אליו
כ-forwarding / delegation. לכן מריצים חיפוש אחד לכל תיבה עם `to:` כדי לשייך כל שולח למחלקה:

```
תיבות i-feel (הרץ חיפוש נפרד לכל אחת):
1. to:sales@i-feel.co.il     after:{מתאריך} before:{עד תאריך}
2. to:support@i-feel.co.il   after:{מתאריך} before:{עד תאריך}
3. to:office@i-feel.co.il    after:{מתאריך} before:{עד תאריך}
4. to:account@i-feel.co.il   after:{מתאריך} before:{עד תאריך}
5. to:myhome@i-feel.co.il    after:{מתאריך} before:{עד תאריך}
6. to:oren@i-feel.co.il      after:{מתאריך} before:{עד תאריך}
7. in:inbox -to:sales@i-feel.co.il -to:support@i-feel.co.il -to:office@i-feel.co.il -to:account@i-feel.co.il -to:myhome@i-feel.co.il -to:oren@i-feel.co.il
                             after:{מתאריך} before:{עד תאריך}   ← רשת ביטחון לתפוס מה שלא נתפס ב-to:
```

טיפים מריצות קודמות:
- `before:` הוא אקסקלוסיבי — כדי לכלול את היום האחרון, שים את היום שאחריו.
- עבור על **כל דפי התוצאות** לפי `nextPageToken` — אל תסמוך על `resultCountEstimate`
  (הוא מחזיר "201" קבוע לשאילתות גדולות). אם תקופה ארוכה מחזירה מאות שרשורים, פצל לחודשים.
- Gmail מחזיר שרשור אם **הודעה אחת** בו בטווח, ו-`to:` תופס גם CC — סנן ידנית הודעות
  שמחוץ לטווח בתוך שרשורים תואמים.
- ה-snippets שחוזרים מ-search_threads מספיקים בדרך כלל לחילוץ שם/מייל/תאריך —
  אל תקרא get_thread לכל שרשור, רק כשה-snippet לא מספיק להכרעה.

מכל שרשור חלץ את **השולחים הנכנסים** (לא אנחנו): שם מלא + כתובת מייל + תאריך המייל הראשון + לאיזו תיבה פנה.
נמענים של מיילים יוצאים שלנו (הצעות מחיר וכו') — לא אוספים; רק מי שכתב אלינו.

### מסננים — את אלה לא אוספים
- כתובות `@i-feel.co.il` (אנחנו)
- אוטומציה: `noreply`, `no-reply`, `donotreply`, `mailer-daemon`, `notification`, `notifications`,
  `alert`, `newsletter`, `info@` של ספקי שירות גדולים
- דומיינים של מערכות: `google.com`, `facebookmail.com`, `tiktok.com`, `monday.com`, `smoove.io`,
  `make.com`, `paypal`, בנקים, חברות אשראי
- כשיש ספק אם זה אדם אמיתי או רובוט — הסתכל על נושא המייל. פנייה אנושית נשארת ברשימה.

**ספקים ואנשי מקצוע** (אדריכלים, חשמלאים, יבואנים) — כן לאסוף, אבל לסמן `supplier` בעמודת notes.
אורן יחליט בעצמו אם לכלול אותם בדיוור.

## שלב 3 — סיווג קשר והרשאת דיוור לפי סעיף 30א לחוק התקשורת

הפרד תמיד בין **סוג הקשר** לבין **הבסיס להרשאת דיוור**. סטטוס `לקוח קיים` הוא עובדה עסקית בלבד
ואינו, כשלעצמו, היתר לצרף אדם לרשימת דיוור.

לכל איש קשר קבע `spam_law_status`:

| סטטוס | מי נכנס |
|--------|---------|
| `לקוח קיים` | עסקה נסגרה / פרויקט פעיל / הותקן / קיבל הצעת מחיר והתקדם |
| `פנה מיוזמתו` | שלח מייל לתיבות שלנו אבל אין עסקה סגורה (ליד, שאלה, ספק) |
| `לא ידוע` | נמצא רק במאנדיי בלי תכתובת, או שאי אפשר לקבוע |

בנפרד, קבע `mailing_permission`:

| ערך | מתי להשתמש |
|-----|-------------|
| `explicit-consent` | קיימת הסכמה מפורשת ומתועדת לקבלת דברי פרסומת בכתב, במייל או בשיחה מוקלטת, ולא נמצאה הודעת סירוב מאוחרת יותר |
| `customer-exception-documented` | יש תיעוד שכל תנאי סעיף 30א(ג) מתקיימים: הפרטים נמסרו במהלך רכישה או משא ומתן; בעת המסירה נמסר שישמשו לפרסום; ניתנה אפשרות לסרב והיא לא נוצלה; והדיוור הוא על מוצר או שירות מסוג דומה |
| `opt-in-required` | ברירת המחדל: אין תיעוד מלא להסכמה או לכל תנאי חריג הלקוח הקיים |
| `do-not-mail` | קיימת הודעת סירוב, הסרה או בקשה שלא לקבל דיוור; ערך זה גובר על כל הסכמה קודמת |

אל תסיק `explicit-consent` או `customer-exception-documented` מסטטוס במאנדיי, מהתכתבות שירות,
מהצעת מחיר או מעצם היות האדם לקוח. בהיעדר ראיה מתועדת, השתמש ב-`opt-in-required`.

לנמען שהוא בית עסק ניתן להכין פנייה חד-פעמית שמטרתה לבקש הסכמה לקבלת דברי פרסומת;
אל תשלב בפנייה זו תוכן שיווקי ואל תניח שהחריג חל על אדם פרטי. אם זהות הנמען או הבסיס המשפטי
אינם ברורים, אל תדוור והעבר לבדיקת יועץ משפטי. ההנחיות בסקיל הן כלל עבודה שמרני, לא ייעוץ משפטי.

**אם מאנדיי לא זמין:** סווג `לקוח קיים` רק כשיש עדות מפורשת בתכתובת עצמה
(הסכם שירות, התקנה פעילה, תכניות פרויקט בעבודה), אך השאר את `mailing_permission` על
`opt-in-required` אלא אם נמצא תיעוד נפרד לאחד מבסיסי ההרשאה שלעיל.

### מצב קהל ממוקד לעדכון סרטון פרויקט

כאשר הבקשה מגיעה מ־`ai-sales-manager` עבור עדכון הסרטון השבועי, קרא בנוסף את לוח
`מאגר אנשי קשר / מקצוע` (`3040781819`) במאנדיי, בלי לשנות אותו. בדוק את ערכי `תפקיד`, הקבוצה
והערות בפועל, ואל תנחש מקצוע משם האדם בלבד. בנה פלח אחד לפי סוג הסרטון:

- `BMS`: יועצי חשמל, קבלני חשמל ואנשי קשר קיימים מסימנס שעיסוקם המתועד רלוונטי לבקרת מבנה;
- `MULTIFAMILY`: יזמי בנייה ויועצי חשמל שעיסוקם המתועד רלוונטי לבנייה רוויה;
- `VILLA`: אדריכלים ואדריכליות.

החזר רק רשומות עם `explicit-consent` או `customer-exception-documented`. החרג תמיד
`opt-in-required` ו־`do-not-mail`, נקה כפילויות לפי מייל, והחרג נמענים שכבר קיבלו את אותו סרטון.
בכל שבוע בחר קבוצה אחרת מתוך הקהל הזכאי לפי היסטוריית השליחות שמספק מנהל המכירות. הסקיל
מכין את הקהל בלבד; מאיה מכינה את הטיוטה ושולחת רק לאחר אישור מפורש.

## שלב 4 — איחוד, ניקוי והפקת CSV

1. בנה קובץ JSON של כל אנשי הקשר בפורמט:

```json
[
  {
    "email": "dani@example.com",
    "first_name": "דני",
    "last_name": "כהן",
    "phone": "0521234567",
    "source": "gmail:sales",
    "spam_law_status": "פנה מיוזמתו",
    "mailing_permission": "opt-in-required",
    "first_seen": "2026-06-15",
    "notes": ""
  }
]
```

   ערכי `source`: `gmail:sales` / `gmail:support` / `gmail:office` / `gmail:account` /
   `gmail:myhome` / `gmail:oren` / `monday` — ואם נמצא בכמה, שרשר עם `+` (למשל `gmail:sales+monday`).

2. שמור את ה-JSON בתיקיית העבודה תחת `mailing-lists\contacts-raw-{תאריך}.json`
   (פורמט תאריך בשמות קבצים: `YYYY-MM-DD`).

3. הרץ את הסקריפט המצורף לסקיל (`scripts/build_csv.ps1`, יושב בתיקיית הסקיל ליד SKILL.md) —
   הוא עושה דה-דופליקציה לפי מייל (case-insensitive), מיזוג נתונים (שם/טלפון ממאנדיי גוברים
   על Gmail), ולידציה של כתובות, סינון ביטחון של noreply, ופלט CSV בקידוד UTF-8 עם BOM
   (כדי שעברית תיפתח נכון ב-Excel וב-Smoove):

```
powershell -ExecutionPolicy Bypass -File "{תיקיית הסקיל}\scripts\build_csv.ps1" -InputJson "mailing-lists\contacts-raw-{תאריך}.json" -OutputCsv "mailing-lists\smoove-import-{תאריך}.csv"
```

   אם הסקריפט לא נגיש מסיבה כלשהי — בצע את אותה לוגיקה בעצמך (הכללים מתועדים בראש הסקריפט).

4. הקובץ הסופי: `mailing-lists\smoove-import-{תאריך}.csv` עם העמודות:
   `email, first_name, last_name, phone, source, spam_law_status, mailing_permission, first_seen, notes`
   (Smoove ממפה עמודות בזמן ייבוא — אין צורך בכותרות בעברית).

## שלב 5 — דוח סיכום לאורן

בסוף הריצה הצג (בצ'אט, בעברית):

```
📬 רשימת דיוור — {טווח תאריכים}

נאספו: X אנשי קשר ייחודיים (Y לפני ניקוי כפילויות)
  לפי מקור:   Gmail — X | מאנדיי — X | שניהם — X
  לפי סיווג:  לקוח קיים — X | פנה מיוזמתו — X | לא ידוע — X
  לפי הרשאה:  הסכמה מפורשת — X | חריג לקוח מתועד — X | נדרש opt-in — X | לא לדוור — X

⚠️ הערות: {תיבות שלא נסרקו / מאנדיי לא מחובר / כתובות חשודות שסוננו}

📄 הקובץ: mailing-lists\smoove-import-{תאריך}.csv
   ייבוא ל-Smoove: אנשי קשר ← ייבוא ← בחר קובץ ← מיפוי עמודות
```

והזכר לאורן: אפשר לייבא לרשימת דיוור פעילה רק רשומות עם `explicit-consent` או
`customer-exception-documented`. את `opt-in-required` יש להעביר למסלול הרשמה/אישור מתאים,
ואת `do-not-mail` יש להחריג מכל שליחה. Smoove תומכת בטופס הרשמה.
