# Content Inbox — מהעלאה של קרן ועד תוכן חי באתר

## איך הצינור בנוי

- קרן מעלה תכנים (Word / טקסט / תמונות / קטלוגים) לתיקיית `content-inbox/` בריפו
  `oren341965/i-feel-site` **דרך Pull Request בלבד** — branch `main` מוגן, שום דבר לא
  נכנס בלי אישור אורן. המדריך שלה בעברית: `D:\Claude\ifeel-keren\`.
- התיקייה לא משפיעה על האתר החי. הפרסום בפועל: אישור אורן → מיזוג → שילוב בדפי האתר
  → build → ‎/deploy-ifeel.
- הריפו המקומי: `C:\Users\USER\i-feel-site`. ‏gh CLI מחובר ומאומת.
- הערה: מיזוג ל-main המוגן דורש `gh pr merge --admin` (אורן הוא הבעלים).

## שלב 1 — מה חדש?

```powershell
gh pr list --repo oren341965/i-feel-site --state open --json number,title,author,files,createdAt
```

- סנן PRים שנוגעים ב-`content-inbox/`.
- PR שנוגע ב-`src/`, `public/` או קבצי שורש **לא אמור להגיע מקרן** — סמן לאורן כחריג
  ואל תמזג בלי בדיקה קפדנית.
- אין PRים פתוחים? בדוק גם תוכן שמוזג ועדיין לא טופל: קבצים ב-`content-inbox/`
  (אחרי `git pull`) שאינם `README.md` ואינם תחת `processed/`.
- אין כלום → דווח "ה-inbox ריק" וסיים.

## שלב 2 — קריאת התוכן וסיכום לאורן

לכל PR רלוונטי:

```powershell
gh pr view <N> --repo oren341965/i-feel-site --json title,body,files
gh pr checkout <N>        # מתוך C:\Users\USER\i-feel-site
```

- קרא את הקבצים: ‎.docx — פתח עם סקיל ה-docx; טקסט/‏Markdown — ישירות; תמונות — הצג לאורן
  מה יש; PDF — סקיל ה-pdf.
- סכם לאורן: מה הגיע, על איזה נושא, מה איכות הטקסט, ומה **ההמלצה שלך** לכל פריט:
  - **דף חדש** — רק אם אין דף קיים שמכסה את הנושא (חוק strengthen-don't-duplicate).
  - **חיזוק דף קיים** — ברירת המחדל כשיש כבר דף בנושא; ציין איזה דף.
  - **גלריה** — תמונות פרויקטים → ‎/gallery-add.
  - **קטלוג** — PDF ל-`public/assets/catalogs/` + הוספה לדף `/catalogs/`.
  - **לא לשימוש** — תוכן חלש/כפול/בעייתי; הסבר למה.
- **עצור כאן וחכה להחלטת אורן.** שום דבר לא מתמזג ולא מתפרסם בלי אישור מפורש שלו.

## שלב 3 — אחרי אישור אורן

1. מזג את ה-PR:
   ```powershell
   gh pr merge <N> --repo oren341965/i-feel-site --squash --admin
   git checkout main; git pull origin main
   ```
2. שלב את התוכן לפי ההחלטה:
   - דף חדש → הפעל את הצ'קליסט המלא של **/new-page** (כולל sitemap ידני!).
   - חיזוק דף קיים → ערוך את `src/page-html/<slug>.html`, עדכן `lastmod` ב-sitemap.
   - תמונות גלריה → **/gallery-add**.
   - קטלוג → העתק ל-`public/assets/catalogs/` בשם kebab-case + הוסף כרטיס בדף הקטלוגים.
   בעריכת טקסט של קרן: שמור על הקול שלה אבל אכוף את הכללים — טלפון `03-508-9553` בלבד,
   טענות אמון מאושרות בלבד (מאז 2008, ‏9,000+ לקוחות, ‏180+ פרויקטי BMS), בלי הבטחות מחיר חדשות.
3. **סדר את ה-inbox**: העבר את קבצי המקור שטופלו ל-`content-inbox/processed/YYYY-MM/`
   (git mv, לא מחיקה — המקור של קרן נשמר תמיד), עם commit שמתאר מה נעשה בכל קובץ.
4. Build (`npm run build`) → הרץ **/deploy-ifeel** או אמור לאורן להריץ.

## שלב 4 — משוב לקרן (דרך אורן)

בסוף הריצה תן לאורן פסקה קצרה בעברית שהוא יכול לשלוח לקרן: מה נקלט, מה עלה לאתר
(עם קישורים חיים), ומה כדאי לשפר בהעלאה הבאה (שמות קבצים, גודל תמונות, חוסרים בטקסט).
זה מה ששומר על הצינור עובד לאורך זמן.

## אל-תעשה

- אל תמזג PR ואל תפרסם תוכן בלי אישור מפורש של אורן באותה שיחה.
- אל תמחק קבצים שקרן העלתה — רק להעביר ל-`processed/`.
- אל תמזג PR שנוגע בקבצים מחוץ ל-`content-inbox/` בלי בדיקה ואישור נפרדים.
- אל תפרסם טקסט של קרן כמו-שהוא בלי לעבור על טלפונים, טענות מספריות וכפילות מול דפים קיימים.
